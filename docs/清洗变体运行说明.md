# 清洗变体的运行和核验

固定范围和处理规则见[协议](清洗变体实验协议.md)。按README安装 `requirements-formal-lock.txt`，准备官方数据和固定GloVe。训练配置仍为 `configs/formal_ce.json`；权重通过独立ID映射文件传入，不改训练数据列。

## 完整重跑

每个输出目录必须不存在。已有同哈希重建输入时可直接运行第二条命令；重跑请使用新的目录名。

```powershell
.\.venv\Scripts\python.exe -m c04.prepare_formal_data --results reports/stage3/formal_idn10_v2 --output data/cleaning_variant_input
.\.venv\Scripts\python.exe -m c04.run_cleaning_variants --source data/cleaning_variant_input/matrix.json --output artifacts/replay_cleaning_variants --device cuda
.\.venv\Scripts\python.exe -m c04.cleaning_variant_results --source artifacts/replay_cleaning_variants --results reports/replay_cleaning_variants
.\.venv\Scripts\python.exe -m c04.analyze_cleaning_variants --results reports/replay_cleaning_variants --output docs/重跑清洗变体结果
```

顺序训练12次：CE重跑、OOF硬重标注、OOF概率加权、训练内打分删除后重训，各三个种子。已有15个OOF模型的概率来自发布资产，直接复用，费用在结果中另列。取消OOF变体使用本轮CE模型对其自身训练样本产生概率，这些概率明确标记为in-sample，不是折外预测。

CE重跑的测试预测必须与已有带噪CE逐字节一致，否则流水线停止，不继续其他变体。训练/选模只读取训练与验证划分；测试评估不会修改规则或配置。训练内打分用最佳验证检查点，与清洗后重训分别记录。

## 只核验已发布证据

Git新检出目录中准备固定官方数据及依赖，无需下载GloVe或训练即可执行：

```powershell
.\.venv\Scripts\python.exe -m c04.cleaning_variant_results --results reports/stage4/cleaning_variants_idn10_v2
.\.venv\Scripts\python.exe -m c04.analyze_cleaning_variants --output docs/阶段4清洗变体结果
```

核验会重算12组预测指标和混淆矩阵、重放标记与处理决策、核对训练文件哈希、训练专用词表、固定配置、验证输入、权重哈希与全局均值1，并核对普通CE重跑。训练内概率还检查样本ID、观测标签、打分模型与训练输入指纹。

提交 `541bdbb` 已在独立本地Git克隆中通过上述核验，重生成的分析JSON与发布版本相同，克隆工作区干净。检查复用原虚拟环境和固定官方原始文件，没有重跑12次训练；范围见 `reports/stage4/cleaning_variants_idn10_v2_checkout_check.json`。

结果证据不包含完整模型权重；仅凭概率文件和哈希不能验证模型是否确实生成该概率，完整过程需重跑训练/预测入口。权重文件进入检查点的训练指纹，恢复训练时必须再次传入同一文件，缺失或变化会被拒绝。例如：

```powershell
.\.venv\Scripts\python.exe -m c04.train --train <weighted-run>/input/train.jsonl --sample-weights <weighted-run>/input/weights.json --config configs/formal_ce.json --seed 17 --device cuda --output <weighted-run>/training --resume --epochs 35
```

上例仅说明恢复接口，不属于本轮30轮正式预算。早停已结束的运行仍禁止恢复；不能通过续训覆盖正式结果。

## 加权断点恢复检查

此项使用seed=17的观测输入和权重，单独比较连续两轮与一轮后恢复至两轮。它不计入12次正式训练；新增3次有效训练调用，共4轮，另有2次应被拒绝的恢复调用。需要CUDA和固定GloVe，输出目录须不存在。

```powershell
.\.venv\Scripts\python.exe -m c04.check_weighted_resume --train artifacts/stage4_cleaning_variants_idn10_v2/weighted/k10_s17/input/train.jsonl --weights artifacts/stage4_cleaning_variants_idn10_v2/weighted/k10_s17/input/weights.json --output artifacts/replay_weighted_resume --report reports/replay_weighted_resume_check.json
```

本次检查的模型参数逐项相等，训练损失与验证指标轨迹完全一致；恢复时缺少权重或改变ID对应权重均被拒绝。结果见 `reports/stage4/weighted_resume_check.json`。从新检出目录执行时，可先按完整重跑入口生成输入，或从已发布的逐样本证据重建相同ID权重映射。

# 基线运行说明

## 环境

Python 3.12。数据依赖为NumPy 2.3.5；训练使用PyTorch 2.9.1，绘图使用Matplotlib 3.10.7。GPU验收环境为Windows 11、RTX 3060 Laptop 6GB、CUDA 12.6 wheel。

在仓库根目录执行：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-data.txt
.\.venv\Scripts\python.exe -m pip install torch==2.9.1 --index-url https://download.pytorch.org/whl/cu126
.\.venv\Scripts\python.exe -m pip install -r requirements-train-lock.txt --extra-index-url https://download.pytorch.org/whl/cu126
```

`requirements-train-lock.txt`固定本阶段已使用的完整GPU环境。CPU环境可使用PyTorch官方CPU源，再安装直接依赖：

```powershell
.\.venv\Scripts\python.exe -m pip install torch==2.9.1 --index-url https://download.pytorch.org/whl/cpu
.\.venv\Scripts\python.exe -m pip install -r requirements-train.txt
```

CPU可运行相同代码，但不保证与GPU逐位相同。精确断点续训要求Python、NumPy、PyTorch、GPU型号与设备类型一致。

## 下载数据与词向量

```powershell
.\.venv\Scripts\python.exe -m c04.prepare
.\.venv\Scripts\python.exe -m c04.prepare_glove
```

GloVe为Stanford `glove.6B.100d.txt`，其压缩包约822MiB，仅解压100维成员。下载中断时重复执行同一命令，Range分段请求从已写入的字节继续；解压前后分别核对固定SHA256。下载文件和处理数据位于 `data/`，不提交Git。

若Windows GPU包经pip下载时反复中断，可使用同一分段下载器，并核对PyTorch官方索引提供的哈希：

```powershell
.\.venv\Scripts\python.exe -m c04.download --url "https://download-r2.pytorch.org/whl/cu126/torch-2.9.1%2Bcu126-cp312-cp312-win_amd64.whl" --output "data/dependencies/torch-2.9.1+cu126-cp312-cp312-win_amd64.whl" --sha256 f2f1c68c7957ed8b6b56fc450482eb3fa53947fb74838b03834a1760451cf60f
.\.venv\Scripts\python.exe -m pip install "data/dependencies/torch-2.9.1+cu126-cp312-cp312-win_amd64.whl" --extra-index-url https://download.pytorch.org/whl/cu126
```

该替代命令仅适用于Windows x64、CPython 3.12。其他平台使用对应的官方wheel。

## 单组训练与评估

```powershell
.\.venv\Scripts\python.exe -m c04.train --train data/processed/fewshot/seed_17/k_10.jsonl --seed 17 --device cuda --output artifacts/clean_k10_s17
.\.venv\Scripts\python.exe -m c04.evaluate --checkpoint artifacts/clean_k10_s17/best.pt --device cuda --output artifacts/eval_clean_k10_s17
```

省略 `--device` 自动选择GPU或CPU。训练数据只含 `id/text/label`，词表只使用该训练文件。验证集使用官方完整验证划分，并验证数据及类别映射校验值。测试入口单独读取官方4500条ID测试样本和1000条OOS测试样本。

默认配置见 `configs/baseline.json`：100维GloVe嵌入参与微调，单层双向LSTM每个方向128维，掩码注意力池化，输入及分类头dropout为0.3；长度40、batch 64、AdamW学习率1e-3、weight decay 0.01、梯度裁剪5，最多5轮，以验证宏F1早停，耐心2轮。

每组训练输出包括：

- `assets/`：训练词表、对齐嵌入矩阵和覆盖率清单。
- `run_from_epoch_*.json`：实际配置、种子、环境、Git版本、训练/验证校验值。
- `history.json`：逐轮训练/验证损失、验证宏F1/准确率、含验证耗时、显存。
- `best.pt`：按验证宏F1选择的模型；`last.pt`：最近一轮模型、优化器及随机状态。
- `summary.json`：最佳轮次、总轮数和训练汇总。

评估输出包括 `metrics.json`、150类 `per_class.csv`、原始计数混淆矩阵CSV及归一化图、OOS ROC、学习曲线、5500条预测明细和原始logits。OOS为正类，分数为 `1-max softmax`，AUROC不依赖阈值。

显存字段中 `peak_gpu_memory_mb` 表示PyTorch峰值已分配显存，单位MiB；`peak_gpu_reserved_mb`表示缓存分配器峰值保留显存。两者均不等于整卡总占用，不能用来推断驱动/CUDA上下文开销。

输出目录非空时程序拒绝覆盖。新实验使用新目录；续训使用原目录和 `--resume`。

## 断点续训

```powershell
.\.venv\Scripts\python.exe -m c04.train --train data/processed/fewshot/seed_17/k_10.jsonl --seed 17 --epochs 1 --device cuda --output artifacts/resume_example
.\.venv\Scripts\python.exe -m c04.train --train data/processed/fewshot/seed_17/k_10.jsonl --seed 17 --epochs 5 --device cuda --output artifacts/resume_example --resume
```

`--epochs 5`表示总目标5轮，而不是额外训练5轮。配置仅允许修改总轮数；数据、种子或其他配置变化时拒绝续训。早停已触发的运行不继续训练，预算敏感性实验使用新目录。

检查连续训练与重启续训：

```powershell
.\.venv\Scripts\python.exe -m c04.check_resume --train data/processed/fewshot/seed_17/k_5.jsonl --device cuda --output artifacts/resume_check
```

## 三种子基线矩阵

```powershell
.\.venv\Scripts\python.exe -m c04.run_baseline_matrix --device cuda --output artifacts/clean_baseline_matrix
```

默认运行17/42/2026三个种子，以及每类5/10/20/100条四个规模，共12组训练和独立评估；每组最多5轮。可用 `--shots 10 100` 限定规模。脚本输出逐组日志、预测和检查点，汇总均值及样本标准差(ddof=1)。完整权重留在本地，可根据代码、配置和校验值重建。

导出逐样本预测、日志和图表，并重新计算指标：

```powershell
.\.venv\Scripts\python.exe -m c04.export_results --matrix artifacts/clean_baseline_matrix/matrix.json --output reports/clean_baseline_export
.\.venv\Scripts\python.exe -m c04.check_results --results reports/clean_baseline_export
```

检查仓库已保存的12组结果无需重新训练：

```powershell
.\.venv\Scripts\python.exe -m c04.check_results --results reports/stage2/clean_runs
```

延长训练仅用于预算诊断，单独指定新目录，例如：

```powershell
.\.venv\Scripts\python.exe -m c04.train --train data/processed/fewshot/seed_17/k_10.jsonl --seed 17 --epochs 30 --device cuda --output artifacts/diagnostic_k10_s17_e30
```

30轮诊断结果与5轮主设置分别记录。后续如调整正式训练预算，应在运行鲁棒方法前固定统一预算，并同步考虑五折清洗的额外成本。

# 补充实验运行与本地证据

项目实文件位于 `D:\模式识别作业\c04-repro`，原C盘路径通过目录联接访问同一份文件。迁移时逐文件核对98172个文件的SHA256；原虚拟环境和新虚拟环境都能识别CUDA。迁移清单在项目父目录的 `tmp/migration_20261119.json`，不上传Git。

## 环境

本轮另建 `tmp/final_environment`，重新安装 `requirements-formal-lock.txt`。固定torch wheel可以从已下载的 `data/dependencies/` 安装，再安装其余锁定依赖；复用本机Python 3.12基础解释器，不复用旧环境site-packages。

```powershell
python -m venv tmp/final_environment
.\tmp\final_environment\Scripts\python.exe -m pip install -r requirements-formal-lock.txt
.\tmp\final_environment\Scripts\python.exe -m pip check
.\tmp\final_environment\Scripts\python.exe -m unittest discover -s tests -v
```

这里的 `python` 需要指向Python 3.12。数据、GloVe和MiniLM按README及固定版本准备；使用已有本地资产时仍核对校验值。


补充训练复用已有核心矩阵、消融、固定MiniLM向量与对应原始训练产物；它不是仅克隆仓库就能绕过前面阶段的独立入口。前三阶段运行方法仍见各阶段说明。`completion_experiments` 只跳过已登记完成的结果；任意中断的训练目录不保证自动恢复，需先保留并移走未完成目录，不能覆盖已有文件。

本次因C盘容量中断的两条路线已原样存档到 `artifacts/interrupted_before_d_resume/`，清单记录全部文件校验值。已完成的CE/GCE和SVM17保留。额外中断成本在清单中单列，不作为计划内新增拟合计数。

统一验收入口：

```powershell
.\tmp\final_environment\Scripts\python.exe -m c04.final_acceptance
.\tmp\final_environment\Scripts\python.exe -m c04.experiment_inventory
```

`final_acceptance` 必须在补充训练结束后运行；`--wait` 可等待当前训练完成后顺序执行，避免同时使用GPU。它重新训练整组IDN30%、10-shot、三个种子的干净CE/带噪CE/GCE/五折清洗后CE：12次最终拟合加15次OOF拟合。比较预测字节、选中模型参数，并重放新训练模型及OOF概率。其他既有条件逐一核验并重放权重，不宣称全部重新训练。

## 结论边界

完成实验与研究目标达成分别判断。q扫描保留全部结果，主q不变；清洗失败不能删去。三种子均值、标准差、配对t区间和精确Wilcoxon同时报告，不把小样本p>0.05写成性能等价或OOS非劣。

CNN v1的未达标记录保留。SVM v2采用验证集选择的线性词频模型，公开数值接近也只说明所声明实现的指标差值，不证明恢复了论文未公开的原始代码。

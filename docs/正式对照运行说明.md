# 三方法配对对照的重跑与验收

对照范围固定为10-shot、30%噪声、三个种子，按真实MiniLM IDN和对称噪声分别归档。训练预算见[正式对照协议](正式对照协议.md)，其他样本量和噪声比例尚未纳入本轮。旧5轮结果保留。

## 运行条件

Python 3.12.14、Windows、PyTorch 2.9.1+cu126、可用CUDA显卡。CPU入口可运行，但不保证与GPU逐位相同。项目虚拟环境中的实际依赖冻结在 `requirements-formal-lock.txt`，可安装为：

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-formal-lock.txt
.\.venv\Scripts\python.exe -m pip check
```

先按README准备固定官方数据及GloVe。正式对照使用保存的观测噪声标签重建相同训练输入，不需要重新下载句子编码器。重新生成噪声的编码器与构造协议保留在阶段三资产记录中。

## 仅核验已发布结果

```powershell
.\.venv\Scripts\python.exe -m c04.formal_results --results reports/stage3/formal_idn10_v2
```

该命令校验导出哈希、官方测试ID/真值，独立重算12组预测的指标与混淆矩阵，并从OOF概率重建三个种子的清洗决策。每个折还核对训练/留出隔离、恰好一次覆盖和训练专用词表。清洗估计器不读取官方干净训练标签。

## 完整训练重跑

输出目录必须不存在，避免误覆盖历史运行。重建噪声文件时检查每个种子的原始少样本数据哈希与观测标签哈希。

```powershell
.\.venv\Scripts\python.exe -m c04.prepare_formal_data --output data/formal_idn10_v2
.\.venv\Scripts\python.exe -m c04.run_formal_comparison --source data/formal_idn10_v2/matrix.json --output artifacts/replay_idn10_v2 --device cuda
.\.venv\Scripts\python.exe -m c04.formal_results --source artifacts/replay_idn10_v2 --results reports/replay_idn10_v2
```

顺序运行27次训练：3个干净CE、3个带噪CE、3个GCE，以及15个OOF模型和3个清洗后CE。验证集选模，测试仅独立评估。每组导出5500条ID/OOS预测，不上传模型权重。完整检查点、OOF日志及中间文件保留在本地 `artifacts/`。

## 对称30%扩展

使用同一虚拟环境和官方处理数据。可直接通过固定生成器构造本轮的三个观测输入，再完整训练：

```powershell
.\.venv\Scripts\python.exe -m c04.prepare_symmetric_comparison --output data/formal_sym10_v2_source
.\.venv\Scripts\python.exe -m c04.run_formal_comparison --source data/formal_sym10_v2_source/matrix.json --output artifacts/stage3_formal_sym10_v2 --device cuda
.\.venv\Scripts\python.exe -m c04.formal_results --source artifacts/stage3_formal_sym10_v2 --results reports/stage3/formal_sym10_v2
.\.venv\Scripts\python.exe -m c04.analyze_formal_comparison --results reports/stage3/formal_sym10_v2 --output docs/阶段3对称噪声正式结果
```

训练入口只读取观测 `noise/train.jsonl`，不读取旁边的 `audit/`。首次构造的三个训练哈希已核对与阶段1相同，见 `reports/stage3/symmetric30_preflight.json`。对称噪声使用原有生成协议，没有根据上一轮清洗结果重新挑选翻转样本。

对发布结果的核验和输入重建使用显式结果目录，避免误用默认IDN资产：

```powershell
.\.venv\Scripts\python.exe -m c04.formal_results --results reports/stage3/formal_sym10_v2
.\.venv\Scripts\python.exe -m c04.prepare_formal_data --results reports/stage3/formal_sym10_v2 --output data/replay_sym10_v2
.\.venv\Scripts\python.exe -m c04.run_formal_comparison --source data/replay_sym10_v2/matrix.json --output artifacts/replay_sym10_v2 --device cuda
```

所有输出目录都需尚未存在；重跑时使用新名字。对称结果核验还会独立调用固定噪声生成器，确认保存的观测标签确实来自对应种子。

两组结果均导出并验收后，可生成描述性比较表和图：

```powershell
.\.venv\Scripts\python.exe -m c04.compare_noise_conditions --output docs/阶段3两类噪声比较
```

该入口同时核对模型配置和三个干净参考的预测文件。噪声类型间使用不同随机命名空间，翻转集合不相同；比较不能解释为仅改变语义相似性后的因果效应。

## 口径

- 均值和样本标准差使用三个种子，F1保持率逐种子除以同预算干净CE，再汇总。
- 清洗会缩小训练集和词表；相同轮数不等于相同更新次数。OOF额外成本单独记录并计入路线墙钟时间。
- 表中已分配/保留显存为PyTorch进程记录，不等于整卡占用。
- 旧清洗试跑使用的是阈值启发式，不能与本轮cleanlab实现作为同一算法版本直接汇总。
- 本轮是观察过早期探索结果后制定的固定对照；不能声称从未使用过该测试集，也不能据三种子均值直接宣称统计显著或OOS非劣。
